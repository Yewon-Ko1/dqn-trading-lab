# Week 3 회고 (2026-09-10 ~ 2026-09-16) — 원리 정리와 검증 설계

> 학습 흐름: 데이터·평가 기준 → 환경·에이전트 구현 → **원리 정리와 검증 설계** → 설정 동결과 최종 평가

앞 주에 확인한 시드 편차 때문에, 구현을 더 쌓기 전에 사용 중인 구성 요소의 원리를 다시 정리하고 검증 절차를 먼저 설계한 주간입니다. 그 절차로 설계 선택을 실험하는 과정에서 평가 코드와 데이터의 결함을 찾아 수정했습니다. 최신 진행 상태는 루트 [`README.md`](../README.md), 실험 결정은 [`decisions.md`](../decisions.md)를 기준으로 합니다.

## 이번 주 목표

- 모델의 모든 설계 선택에 "왜 그 값인가"를 답할 수 있게 하고, 그 답을 재현 가능한 실험으로 뒷받침한다.

## 완료한 작업

### 1. 구성 요소 원리 재정리

- 텐서와 자동미분, 학습 한 스텝의 구성(손실 계산 → 기울기 초기화 → 역전파 → 갱신)
- 신경망의 계산 구조 — 가중치 합과 활성화 함수, 은닉층 크기와 층수가 표현력·과적합과 갖는 관계, 출력층에 활성화 함수를 두지 않는 이유
- 머신러닝의 구성(데이터·모델·손실·최적화), 지도·비지도·강화학습의 위치, 파라미터와 하이퍼파라미터의 구분, 학습과 추론의 차이
- 손실 함수 — 이상치가 있는 금융 데이터에서 Smooth L1이 갖는 성질
- 최적화 — Adam의 관성과 파라미터별 보폭
- DQN 하이퍼파라미터 6종의 의미 — 할인율과 유효 시야, 리플레이 버퍼, 배치 크기, 타깃 네트워크 갱신 주기, 탐험 감쇠, 에피소드 수

### 2. 선행 연구 검토

- 상태 설계의 세 갈래 비교 — 원시 가격과 포지션만 사용하는 접근, 기술지표와 별도 위험 게이트를 결합한 접근, 국내 지수와 보유 기간을 상태에 포함한 접근. 이후 피처 후보를 고르는 근거로 사용
- 외국인 수급이 수익률을 선행하기보다 추종한다는 국내 실증 연구 확인
- 제한된 학습 예산에서 정책경사 계열이 사실상 학습되지 않는다는 기존 비교 실험 결과를 확인하고, 값 기반 알고리즘을 선택한 근거로 정리

### 3. 검증 프로토콜 수립

- 튜닝 구간과 평가 구간 분리 — 2018년 하락장, 2019년 상승장, 2020년 급락 후 반등장을 튜닝 폴드로 두고 2021년 이후는 설정 동결 전까지 사용하지 않음
- 초기 폴드가 상승장뿐이어서 방어력을 볼 수 없다는 문제를 확인하고 하락장 폴드를 추가
- 후보 변경 조건을 실험 전에 확정 — 기본값 대비 평균 초과수익률 +3%p 이상, 3개 폴드 중 2개 이상 개선, 2018년 방어력 비악화를 모두 충족할 때만 변경
- 시드 10개에서 20개로 확대하고 동률 범위를 표준오차 수준(±3%p)으로 정의
- 실험 범위 확정 — 삼성전자 단일 종목 사례 연구로 한정하고, KODEX 200은 삼성전자와 일간 수익률 상관이 높아 보조 결과로만 사용
- 가설 → 실험 → 결과 → 결정 근거를 [`decisions.md`](../decisions.md)에 단계별로 기록

### 4. 설계 결정 실험

- 에피소드 수(10/20/40) — 학습량을 늘려도 시드 편차가 줄지 않아 기본값 유지
- 관측창 길이(10/20/60) — 짧은 창을 채택했으나 근거 폭이 표준오차 수준임을 함께 기록
- 피처 세트 11종 비교 — 기술지표, 장기 추세(200일선·52주 고점), 시장지수, 투자자 수급, 변동성 국면, 미국 지수를 각각 추가했으나 최소 세트 대비 유의한 개선이 없었음
- 2라운드에서 1위였던 구성이 사용하지 않은 시드로 재검증하자 순위가 뒤집혀, 최소 세트를 최종 채택
- 잦은 매매 제어 — 상태에 보유 기간을 알려주는 방식과 최소 보유기간 제약을 비교해, 제약 방식이 거래 횟수를 절반 이하로 줄이면서 성과를 크게 개선. 제약 길이 3·10·20일도 비교해 중간값 채택
- 지금까지의 설계 선택 중 이 항목의 효과가 가장 컸고, 부진의 원인이 예측력보다 거래비용 쪽에 있었음을 확인

### 5. 실험 중 발견한 오류와 데이터 정제

- 평가 구간 정합 오류 — 에이전트는 관측창 길이만큼 늦게 거래를 시작하는데 기준선은 연초부터 평가되던 문제를 발견. 직전 거래일을 워밍업으로 붙여 모든 전략의 평가 구간을 일치시키고, 관측창 비교 실험과 기존 2021~2024년 결과를 최종 근거에서 제외
- 액면분할 거래량 보정 — 가격은 소급 조정되지만 거래량은 조정되지 않아 분할 직후 거래량 지표가 크게 왜곡되던 문제 수정
- 매매정지일 제거 — 시가와 거래량이 0인 행을 거래 가능일에서 제외
- 데이터 시작 구간 확장 — 장기 피처의 워밍업을 확보하기 위해 수집 시작을 앞당기고, 소스의 기간 제한을 다른 소스로 보충한 뒤 겹치는 구간의 가격 기준이 같은지 검증
- 룩어헤드 검사 자동화 — 미래 구간을 잘라내고 다시 계산해도 과거 값이 동일한지 확인. 해외 지수는 국내 거래일 기준 직전 영업일 값만 사용하도록 정렬하고 별도 검사 추가
- 시장·수급·해외 지수 데이터 수집 경로 구성

### 6. 실험 자동화

- 정해 둔 규칙을 코드로 옮긴 자동 튜닝 체인 작성 — 스윕 실행, 규칙 판정, 다음 단계 진행을 사람 개입 없이 연결하고 단계별 판정을 파일로 기록
- 중단 후 재개 기능 — 같은 설정과 같은 데이터로 이미 끝난 실행은 건너뛰고 남은 것만 수행
- 평가 구간을 2021~2025년으로 확장하고 2026년 부분 연도를 보조 결과로 추가하는 것을 설정 동결 전에 등록
- 저장소 정리 — 그동안의 구현과 실험 기록을 단계별 커밋으로 반영

## 배운 점

- 성능 개선보다 평가 정합성이 먼저다. 모든 전략이 같은 날짜에 시작하고 같은 비용을 부담하는지 확인하기 전의 비교는 의미가 없다.
- 후보가 많아지면 우연히 좋은 결과가 반드시 나타난다. 최종 후보는 사용하지 않은 시드로 다시 검증하는 절차를 두었다.
- 입력 정보를 늘리는 것보다 거래비용 구조를 다루는 쪽의 효과가 훨씬 컸다. 원인을 잘못 짚으면 개선 폭이 작은 축에서만 오래 머물게 된다.
- 상태에 정보를 넣어 준다고 학습되는 것은 아니다. 보상에서 신호가 충분히 드러나야 학습이 일어난다.
- 결정 규칙을 코드로 옮기면 결과를 본 뒤 기준을 바꾸는 여지가 사라진다. 실험 기록의 신뢰도는 절차를 언제 정했는지에 달려 있다.
